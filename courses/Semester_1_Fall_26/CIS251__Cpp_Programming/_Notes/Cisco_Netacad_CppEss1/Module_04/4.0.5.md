# 🧩 4.0.5 Improving the << operator

Take a look at the editor above once again.

There are two different ways of using the “<<” operator: one implemented by us and one we got from the streams library. Can you see one subtle difference between them?

Stream operators may be chained like this:

  

```cpp
cout << i << endl;
```

Our operators aren’t that smart (yet). Don’t try to use them like this. It’ll provoke a whole load of compilation errors.

Do we want to improve our operators so they can do the same trick? Of course we do. How do we do it?

Note that the line we quoted above is interpreted by the compiler in the following way:

  

```cpp
(cout << i) << endl;
```

  

This means that **the expression inside the parentheses returns a reference to a stream** (namely: the cout stream) so it can be used (reused) as a left argument for the next "<<" in a chain.

We can do the same thing with our stack, but it means that the operator functions may not be void anymore. They have to return a value as a reference to the stack object – the same object for which the operators were activated for the first time. This is what the declaration should look like:

  

```cpp
(cout << i) << endl;
```

And here goes the improved definition of the operator:

  

```cpp
Stack& Stack::operator<< (int v) throw (stack_overflow) {
    push(v);
    return *this;
}
```

  

As you can see, **the function returns a reference to its maternal object** (or maybe paternal - unfortunately, we don’t know the sex of the object).

We use the this pointer for that purpose. Can you explain why?

It’s time for some tests – the new main function is here:

  
```cpp
#include <iostream>

using namespace std;

int main(void) {
    int i = 2;
    Stack stk;
    stk << 1 << 2 * i;
    stk >> i; cout << i << endl;
    stk >> i; cout << i << endl;
    return 0;
}
```
  

Now we’re going to improve the “`>>`” operator in the same way. It should be easy.

The new declaration goes first:

  

```cpp
Stack& operator >> (int &v) throw(stack_empty);
```

And the new definition:

  

```cpp
Stack& Stack::operator>> (int &v) throw(stack_empty) {
    v = pop();
    return *this;
}
```

The main function needs some amendments too:

```cpp
#include "mystack_04.h"
#include <iostream>

using namespace std;

int main(void) {
    int i = 2, j;
    Stack stk;
    stk << 1 << 2 * i;
    stk >> j >> i;
    cout << j << endl << i << endl;
    return 0;
}
```

Does it work? Yes, it does. Does the pop work in the right order? Try it yourself!
