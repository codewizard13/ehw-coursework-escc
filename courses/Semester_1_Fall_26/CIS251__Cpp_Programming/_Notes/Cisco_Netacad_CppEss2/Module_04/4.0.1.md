# 🧩 4.0.1 Operators – a glance at the past

An **operator** is a symbol designed to **operate** on data – it’s that simple. The C++ language has a wide range of different operators operating on many different types of data. Some of the operators are more universal, some are more specific, some of them are written as **single symbols**, some are **di-graphs** or even **tri-graphs**, other are **keywords**.

All C++ language operators are divided into many groups and there’s more than one classification to help us categorize them. One of the possible classifications is based on a number of arguments. We know that there are:

*   **unary** operators
*   **binary** operators
*   **ternary** operators (to be honest, there’s only one ternary operator in the C++ language)

Some of the operators may belong to more than one of the above groups depending on the context they’re used in, e.g. “+” and “&” (and more besides) may work both as unary and binary operators.

Another classification relies on the location of the operator. We distinguish:

*   **prefix** operators (placed in front of their argument)
*   **postfix** operators (placed after their argument)
*   **infix** operators (placed in between their arguments)

Some of the C++ language operators are, we can say, fairly obvious. One example of an “obvious” operator is “+”. Everybody understands the role of this operator (at least everybody who’s studied maths for a while), how it works and what results we can expect from it.

There is (at least) one “but”. Do you remember when we talked about strings? Do you remember how the “+” operator works when it relates to a string? Its operation isn’t so obvious there and it doesn’t have many of its traditional adding properties (i.e. it isn’t commutative).

How’s it possible that the one and same operator may have such different traits and operate on arguments so different? We know perfectly well that adding numbers requires completely different algorithms from adding (concatenating) strings, and the only similarity lies in the form of the operator.

This isn’t the only case. Note that the “\>>” and “<<” fall into the same basket. Their primary sphere of application is related to integral numbers (that was the very first role of these operators in the “C” language).

As you know, in C++ they’ve gained additional meaning and are commonly used as operators connected with stream input/output operations. We dare say that they appear much more frequently in the second role than in the first.

This is possible by a mechanism similar to function overloading. “C++” allows the programmer **not only to overload functions (to assign a new implementation to the name of an already existing function) but also to overload operators**.

Fortunately, the programmer isn’t allowed to change the existing operator's meaning (e.g. you can’t force “+” to subtract ints or floats) but you can define new domains for it (e.g. strings are a new domain for “+”).

Note that C++ doesn’t allow you to define completely new operators (e.g. you may not define an operator like this: “$#$”). You only can redefine any of the existing operators.
