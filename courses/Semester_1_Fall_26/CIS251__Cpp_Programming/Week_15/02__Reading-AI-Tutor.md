# Week 15: Capstone Integration, Testing, Documentation, and Final Project Preparation

**Purpose:** This page is your primary weekly tutorial. The external resources are supplemental. If you cannot reach every external site, study this page carefully, type and run the examples, complete the practice tasks, and use the AI Tutor for explanations.

## Learning Objectives

*   Translate requirements into a manageable program design.
*   Combine previously learned C++ features without adding new technology.
*   Build a test plan before final submission.
*   Document program structure and AI assistance.
*   Prepare a stable final project demonstration.

**How to study this page:** Read one section at a time. Before running each code example, predict what it will do. Then type it yourself rather than copying it. Modify at least one value or condition and observe the effect.

## 1. Start with Requirements, Not Code

List the required inputs, outputs, data to store, classes, operations, file behavior, and error cases. Then map each requirement to a C++ technique you already know. If a feature requires a technology never taught in the course, simplify the design rather than learning an entirely new framework during the final.

## 2. A Practical Capstone Architecture

A console capstone can be substantial without being technically exotic. For example:

*   a class representing one record;
*   a `vector` storing multiple objects;
*   functions for menus and operations;
*   decisions and loops for interaction;
*   file I/O for persistence;
*   exceptions or validation for error conditions;
*   sorting/searching with STL where useful.

All of those techniques were taught earlier in the course.

## 3. Build in Small Increments

1.  Make the program compile with a minimal menu.
2.  Add one class and test it.
3.  Add the collection and test add/display operations.
4.  Add file save/load and test with a small file.
5.  Add validation/error handling.
6.  Add sorting/searching if required.
7.  Refactor only after functionality is stable.

## 4. Test Plan

Create a table containing a test ID, input or action, expected result, actual result, and pass/fail status. Include normal cases, boundary cases, invalid input, empty data, missing file behavior, and repeated operations.

## 5. Final AI Review

AI Studio may help you review requirements, generate additional tests, explain an error, or critique readability. It should not invent features outside the project scope. After every AI suggestion, compile and test the program yourself and record significant assistance in your log.

## Guided Practice Before Graded Work

1.  Write a one-page requirements checklist for the final project.
2.  Sketch the class(es), vector/collection, major functions, and file format.
3.  Create at least 10 test cases before final submission.
4.  Compile with warnings enabled where possible and resolve understandable warnings.
5.  Practice explaining one class, one function, one test, and one AI-assisted decision aloud.

## Preparing for This Week's Programming Assignment

The final project is cumulative. It should demonstrate concepts already taught in Weeks 1–14. Do not add a GUI framework, database, network API, game engine, or other major technology merely to make the project look more advanced.

**Readiness rule:** You should be able to complete the guided-practice tasks without copying a finished solution before beginning the graded programming assignment.

## Self-Check

Answer these in your own words before moving to graded work. If you cannot answer one, return to the relevant section or ask the AI Tutor for an explanation.

1.  Can you identify where each final-project requirement was taught?
2.  Can you explain every class and function you submit?
3.  Does your test plan include invalid and boundary cases?
4.  Can you explain how AI was used and how you verified its suggestions?

## CIS 251 AI Tutor

**Use the tutor to learn, not to replace your work.** Ask it to explain a concept, trace a small example, help interpret a compiler error, or quiz you. Do not ask it to complete the graded assignment for you.

**Useful prompts:** “Explain this concept in simpler terms.” “Give me a new practice problem like the example.” “Trace this code line by line.” “Explain this compiler error without writing my assignment.”
